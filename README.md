# Классификация обращений в поддержку — роутинг тикетов

Дипломный проект: автоматическая классификация обращений в службу поддержки дейтинг-приложения по 7 категориям. По тексту обращения и профилю пользователя модель определяет, к какому отделу направить тикет.

## Задача

Мультиклассовая классификация в 7 категорий:

| Категория    | Количество | Доля   | Описание |
|--------------|-----------|--------|----------|
| `payment`    | 2 516     | 25.2%  | Проблемы с оплатой и подпиской |
| `bug`        | 1 987     | 19.9%  | Технические неисправности |
| `moderation` | 1 621     | 16.2%  | Вопросы по модерации анкет и фото |
| `account`    | 1 309     | 13.1%  | Доступ к аккаунту, смена данных |
| `complaint`  | 1 307     | 13.1%  | Жалобы на других пользователей |
| `refund`     | 815       | 8.2%   | Возврат средств |
| `other`      | 445       | 4.5%   | Прочее |

Датасет: 10 000 тикетов службы поддержки, предоставлен заказчиком. Тексты на русском языке.

## Признаки

Используются только данные, **доступные в момент создания тикета**.

### Исключены как утечка данных (data leakage)

- `resolution_time_minutes`, `escalated`, `csat_ticket`, `support_response` — появляются только после обработки тикета оператором
- `priority` — в реальном продукте проставляется уже после поступления обращения
- `sentiment_score` — тональность вычисляется отдельной моделью после поступления тикета

Если бы модель видела эти поля, она бы через них почти однозначно восстанавливала целевую категорию — и метрики получались бы нереалистично высокими.

### Используемые признаки

**Числовые (13):** возраст пользователя, метрики активности в приложении (`total_likes`, `total_matches`, `messages_sent`, `active_days_last_week`), история покупок (`boosts_purchased`, `superlikes_purchased`), характеристики сообщения (`message_length_chars`, `message_length_words`), время создания (`hour_of_day`), `past_tickets_count`, `avg_csat_history`, `days_since_registration`.

**Категориальные (6):** `day_of_week`, `gender`, `subscription`, `platform`, `channel`, `language`.

**Текст:** `user_message` — собственно текст обращения.

## Предобработка

### Текст: TF-IDF + отбор признаков через хи-квадрат

Текст обращения — ключевой признак для роутинга. К нему применён двухступенчатый пайплайн:

1. **TF-IDF-векторизация** с параметрами:
   - `max_features=2000` — широкий стартовый словарь
   - `ngram_range=(1, 2)` — униграммы и биграммы для захвата фраз («не работает», «вернуть деньги»)
   - `min_df=5` — отсекаем слова, встреченные менее чем в 5 тикетах (шум и опечатки)
   - `max_df=0.9` — отсекаем слова, встречающиеся в более чем 90% тикетов (автоматический стоп-лист)
   - `sublinear_tf=True` — логарифмирование частоты, чтобы снизить влияние повторов внутри одного сообщения
2. **Отбор признаков через хи-квадрат** — из 2000 токенов оставлены **1000** самых информативных. хи-квадрат измеряет статистическую зависимость между словом и классом: отбрасываются токены, слабо связанные с категорией тикета.

### Категориальные: два подхода

| Модель | Кодирование |
|--------|-------------|
| Logistic Regression, Random Forest, LightGBM | **One-Hot Encoding** (каждое значение → бинарная колонка, всего 20 OHE-колонок) |
| CatBoost | **Target encoding** — нативно через `cat_features`, с ordered boosting для защиты от утечки |

### Числовые

Пропуски заполнены медианой по колонке (актуально для `avg_csat_history` — у новых пользователей без истории тикетов).

### Разбиение

80% train / 20% test, **стратифицированное** — гарантирует одинаковые пропорции классов в обеих выборках. Критично для редкого класса `other` (4.5%).

**Итоговая размерность матрицы признаков:** 1000 TF-IDF + 13 числовых + 20 OHE = **1033 признака**.

## Модели и подбор гиперпараметров

| Модель | Тип | Подбор гиперпараметров |
|--------|-----|------------------------|
| **Logistic Regression** | Линейная | `GridSearchCV` по `C ∈ {0.1, 1.0, 10.0}`, 3-fold CV |
| **Random Forest** | Ансамбль деревьев | `GridSearchCV` по `n_estimators ∈ {200, 300}`, `min_samples_leaf ∈ {1, 2, 5}`, 3-fold CV |
| **LightGBM** | Градиентный бустинг | Перебор 4 конфигураций (`learning_rate` × `num_leaves`) с early stopping |
| **CatBoost** | Градиентный бустинг | Перебор 3 конфигураций (`learning_rate` × `depth`) с early stopping |

Для LightGBM и CatBoost используется `early_stopping_rounds=50` — обучение автоматически останавливается, если качество на валидации не растёт 50 итераций подряд. Это одновременно играет роль тюнинга параметра `n_estimators`.

### Лучшие найденные параметры

- **Logistic Regression:** `C=10.0`
- **Random Forest:** `n_estimators=200`, `min_samples_leaf=1`
- **LightGBM:** `learning_rate=0.05`, `num_leaves=63`
- **CatBoost:** `learning_rate=0.1`, `depth=6`

### Важность признаков

После удаления `priority` и `sentiment_score` модели опираются в первую очередь на **ключевые слова из текста обращения**. Тематический словарь пользователей достаточно устойчив — пользователи с проблемами возврата денег пишут «возврат», «вернуть», «деньги», с проблемами оплаты — «подписка», «премиум», и т. д.

| Модель        | Топ-5 признаков |
|---------------|-----------------|
| Random Forest | `возврат`, `подписку`, `фото`, `аккаунт`, `премиум` |
| LightGBM      | `message_length_chars`, `message_length_words`, `days_since_registration`, `total_likes`, `как` |
| CatBoost      | `tfidf_фото`, `tfidf_подписку`, `tfidf_при`, `tfidf_возврат`, `tfidf_премиум` |

Интересное наблюдение: LightGBM наряду с ключевыми словами активно использует **длину сообщения** (`message_length_chars`, `message_length_words`) и стаж пользователя (`days_since_registration`). Это говорит о том, что тексты в разных категориях различаются ещё и по стилю — жалобы обычно длиннее и эмоциональнее, технические вопросы короче.

## Выводы

### По моделям

**Logistic Regression** — F1 macro 0.8564. Достойный бейзлайн: линейная модель на TF-IDF-признаках уверенно разделяет большинство категорий (F1 по `complaint` и `moderation` выше 0.94). Слабые места — редкий класс `other` (F1=0.67) и наиболее "эмоционально разнородный" `payment` (F1=0.83). Общая разница с ансамблевыми методами (~0.12 по F1 macro) показывает реальный вклад нелинейных взаимодействий признаков.

**Random Forest** — лучший результат: F1 macro 0.9826, время обучения всего 5.2 секунды. Ансамбль из 200 деревьев идеально разделяет четыре из семи категорий (F1 = 1.0 на `complaint`, `moderation`, `refund`, близко к 1.0 на `account`). Модель не требует масштабирования признаков, устойчива к выбросам и "сама" отбирает полезные признаки из большого пространства.

**LightGBM** — F1 macro 0.9800, практически не отстаёт от Random Forest, но в 1.3 раза быстрее (4 с против 5.2 с). В продакшене обычно выбирают именно его из-за скорости инференса и меньшего размера модели на диске.

**CatBoost** — F1 macro 0.9784. Нативная работа с категориальными признаками через target encoding даёт чистый код, но метрики чуть хуже Random Forest и LightGBM, а время обучения 226 секунд — в 40–50 раз больше остальных моделей. В данной задаче CatBoost не оправдывает своей сложности.

### Итоговый ранжир по F1 macro

1. **Random Forest** — 0.9826
2. **LightGBM** — 0.9800
3. **CatBoost** — 0.9784
4. **Logistic Regression** — 0.8564

### Практический вывод

Для боевого решения роутинга обращений оптимальным выбором является **LightGBM**: при почти идентичном Random Forest качестве он быстрее обучается, быстрее делает инференс и легче по памяти. Random Forest — хороший простой резервный вариант, который работает без тонкой настройки. CatBoost в данной задаче не даёт преимуществ. Logistic Regression может использоваться как лёгкий бейзлайн для быстрой проверки пайплайна.

Основные сигналы для классификации — **лексика обращения** (специфические для каждой категории слова) и **стилистические характеристики текста** (длина, эмоциональность, профиль пользователя). Это согласуется с практикой: в реальном продукте человек-оператор тоже в первую очередь смотрит на ключевые слова и общий тон сообщения.
