# Классификация обращений в поддержку Twinby

Дипломный проект: автоматический роутинг тикетов службы поддержки дейтинг-приложения. По тексту обращения и профилю пользователя модель определяет категорию - и тикет попадает в нужный отдел без участия человека.

## Задача

Мультиклассовая классификация в 7 категорий:

| Категория    | Количество | Доля   | Описание |
|--------------|-----------|--------|----------|
| `payment`    | 2 516     | 25.2%  | Проблемы с оплатой и подпиской |
| `bug`        | 1 987     | 19.9%  | Технические неисправности |
| `moderation` | 1 621     | 16.2%  | Вопросы по модерации анкет и фото |
| `account`    | 1 309     | 13.1%  | Доступ к аккаунту, смена данных |
| `complaint`  | 1 307     | 13.1%  | Жалобы на других пользователей |
| `refund`     | 815       | 8.2%   | Возврат средств |
| `other`      | 445       | 4.5%   | Прочее |

Датасет: 10 000 тикетов, 34 признака, текст на русском языке.

## Признаки

Используются только данные, доступные **в момент создания тикета**. Поля `resolution_time_minutes`, `escalated`, `csat_ticket`, `support_response` исключены

**Числовые (14):** характеристики пользователя (`age`, `days_since_registration`, `total_likes`, `total_matches`, `messages_sent` и др.) и метрики самого сообщения (`message_length_chars`, `message_length_words`, `sentiment_score`)

**Категориальные (7):** `day_of_week`, `gender`, `subscription`, `platform`, `channel`, `language`, `priority`

**Текст:** `user_message` → TF-IDF, 500 признаков, биграммы, sublinear TF

## Модели

Сравниваются 4 подхода с разной стратегией представления признаков:

| Модель | Особенность |
|--------|-------------|
| **Logistic Regression** | Линейный бейзлайн. Sparse-матрица: TF-IDF + числовые + OHE |
| **Random Forest** | Ансамбль деревьев. Та же sparse-матрица, не нужно масштабирование |
| **LightGBM** | Градиентный бустинг. Dense-матрица, категории через `categorical_feature` |
| **CatBoost** | Градиентный бустинг. Категории - нативно, без ручного кодирования |

Разбивка: 80% train / 20% test, стратифицированная по целевому классу.

## Выводы

**Logistic Regression** ожидаемо слабее всех - F1 macro 0.83. Линейная граница не справляется с взаимодействиями между текстом и табличными признаками. Хуже всего модель работает на классе `other` (F1=0.68) - он размытый по смыслу и линейно не отделяется.

**Random Forest** - огромный скачок до F1=0.987 при времени обучения всего 1.2 секунды. Ансамбль деревьев хорошо улавливает нелинейные зависимости и не требует никакой настройки гиперпараметров.

**LightGBM** - лучший результат: F1 macro 0.9916, обучение за 4 секунды. При этом качество на самом сложном классе `other` выросло с 0.95 (RF) до 0.97. Оптимальный выбор для продакшена.

**CatBoost** уступает LightGBM по всем метрикам и обучается в 24 раза дольше (96 с). Преимущество - нативная обработка категорий без предобработки, что упрощает пайплайн, но в данном случае не даёт прироста качества.
