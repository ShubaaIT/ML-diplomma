# Классификация обращений в поддержку дейтинг сервиса

## Задача

Мультиклассовая классификация в 7 категорий:

| Категория    | Количество | Доля   | Описание |
|--------------|-----------|--------|----------|
| `payment`    | 2 516     | 25.2%  | Проблемы с оплатой и подпиской |
| `bug`        | 1 987     | 19.9%  | Технические неисправности |
| `moderation` | 1 621     | 16.2%  | Вопросы по модерации анкет и фото |
| `account`    | 1 309     | 13.1%  | Доступ к аккаунту, смена данных |
| `complaint`  | 1 307     | 13.1%  | Жалобы на других пользователей |
| `refund`     | 815       | 8.2%   | Возврат средств |
| `other`      | 445       | 4.5%   | Прочее |

Датасет: 10 000 тикетов, 34 колонки, тексты на русском языке.

## Признаки

Используются только данные, доступные **в момент создания тикета**. Поля `resolution_time_minutes`, `escalated`, `csat_ticket`, `support_response` исключены — они известны только после закрытия обращения и создают утечку данных.

**Числовые (14):** возраст, метрики активности пользователя (`total_likes`, `total_matches`, `messages_sent`, `active_days_last_week`), история покупок (`boosts_purchased`, `superlikes_purchased`), характеристики сообщения (`message_length_chars`, `message_length_words`, `sentiment_score`), `hour_of_day`, `past_tickets_count`, `avg_csat_history`, `days_since_registration`.

**Категориальные (7):** `day_of_week`, `gender`, `subscription`, `platform`, `channel`, `language`, `priority`.

**Текст:** `user_message`.

## Предобработка

### Текст: TF-IDF + отбор признаков через chi²

Текст обращения — ключевой признак для роутинга. К нему применён многоступенчатый пайплайн:

1. **TF-IDF векторизация** с параметрами:
   - `max_features=2000` — широкий стартовый словарь
   - `ngram_range=(1, 2)` — униграммы и биграммы для захвата фраз («не работает», «вернуть деньги»)
   - `min_df=5` — отсекаем слова, встреченные менее чем в 5 тикетах (шум и опечатки)
   - `max_df=0.9` — отсекаем слова, встречающиеся в более чем 90% тикетов (автоматический стоп-лист)
   - `sublinear_tf=True` — логарифмирование частоты, чтобы снизить влияние повторов внутри одного сообщения
2. **Отбор признаков через хи-квадрат** — из 2000 токенов оставлено **1000** самых информативных. хи-квадрат измеряет статистическую зависимость между словом и классом: отбрасываются токены, слабо связанные с категорией тикета.

### Категориальные: два подхода

| Модель | Кодирование |
|--------|-------------|
| Logistic Regression, Random Forest, LightGBM | **One-Hot Encoding** (каждое значение → бинарная колонка, всего 24 OHE-колонки) |
| CatBoost | **Target encoding** — нативно через `cat_features`, с ordered boosting для защиты от утечки |

### Числовые

Пропуски заполнены медианой по колонке (актуально для `avg_csat_history` — у новых пользователей без истории тикетов).

### Разбиение

80% train / 20% test, **стратифицированное** — гарантирует одинаковые пропорции классов в обеих выборках. Критично для редкого класса `other` (4.5%).

## Модели и подбор гиперпараметров

| Модель | Тип | Подбор гиперпараметров |
|--------|-----|------------------------|
| **Logistic Regression** | Линейная | `GridSearchCV` по `C ∈ {0.1, 1.0, 10.0}`, 3-fold CV |
| **Random Forest** | Ансамбль деревьев | `GridSearchCV` по `n_estimators ∈ {200, 300}`, `min_samples_leaf ∈ {1, 2, 5}`, 3-fold CV |
| **LightGBM** | Градиентный бустинг | Перебор 4 конфигураций с early stopping |
| **CatBoost** | Градиентный бустинг | Перебор 3 конфигураций с early stopping |

Для LightGBM и CatBoost используется `early_stopping_rounds=50` — обучение автоматически останавливается, если качество на валидации не растёт 50 итераций подряд. Это одновременно играет роль тюнинга параметра `n_estimators`.

### Лучшие найденные параметры

- **Logistic Regression:** `C=1.0`
- **Random Forest:** `n_estimators=300`, `min_samples_leaf=1`
- **LightGBM:** `learning_rate=0.05`, `num_leaves=31`
- **CatBoost:** `learning_rate=0.05`, `depth=6`

## Выводы

### По моделям

**Logistic Regression** — бейзлайн. F1 macro 0.62 заметно ниже ансамблевых методов. Модель хорошо ловит `payment` (recall 0.90), но почти слепа к редким классам: recall на `other` всего 0.24, на `refund` — 0.31. Причина — линейная граница не справляется со сложными взаимодействиями между текстом и табличными признаками, плюс несбалансированные классы в сочетании с регуляризацией смещают предсказания в сторону массовых категорий. Вывод: на такой смешанной задаче линейная модель архитектурно ограничена — нужны нелинейные методы.

**Random Forest** — лучший результат: F1 macro 0.9895 при времени обучения 6.7 секунды. Ансамбль из 300 деревьев решений идеально разделяет такие чёткие категории, как `account`, `moderation` и `refund` (F1 = 1.0 на каждом). Даже на редком `other` recall составляет 0.955. Модель не требует масштабирования признаков, устойчива к выбросам и хорошо работает на смешанных данных.

**LightGBM** — F1 macro 0.9870, второй по качеству. Быстрее всех обучается (4.4 с) благодаря гистограммному построению деревьев. Чуть хуже Random Forest по абсолютному значению F1, но при продакшен-деплое выигрывает по скорости инференса.

**CatBoost** — F1 macro 0.9826. Нативная работа с категориальными признаками через target encoding даёт чистый код (не нужно OHE), но в данном случае не переигрывает Random Forest. Главный минус — время обучения 244 секунды, в 40 раз дольше LightGBM при худших метриках.

### Итоговый ранжир по F1 macro

1. **Random Forest** — 0.9895
2. **LightGBM** — 0.9870
3. **CatBoost** — 0.9826
4. **Logistic Regression** — 0.6224

### Практический вывод

Для боевого решения роутинга оптимальным выбором является **LightGBM**: метрики практически равны Random Forest, но скорость инференса и размер модели сильно меньше. Random Forest — хороший резервный вариант. CatBoost оправдан, если критично простое добавление новых категориальных признаков без переобучения препроцессора.
